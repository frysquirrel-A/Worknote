02. 데이터 흐름 (Data Lifecycle)

"업무 추가" 버튼을 눌렀을 때 무슨 일이 벌어지는지 단계별로 보여줍니다.

1
UI 입력 (TaskTab)

사용자가 '새 업무'를 입력하고 저장 버튼 클릭

2
Provider 상태 업데이트 (Local)

TaskProvider.addTask() 실행. 즉시 화면에 반영됨 (Optimistic UI)

3
DriveService 호출 (Sync)

DriveService.syncJsonData() 호출. 드라이브의 최신 파일 다운로드 -> 내 데이터 병합(Merge) -> 재업로드.

IF (WiFi Only Mode && Mobile Data) -> STOP Upload
4
Google Drive 저장 완료

worknote_tasks.json 파일이 갱신됨. 이제 다른 팀원들이 앱을 켜면 이 내용을 보게 됨.

03. 상태 관리 (The Brain)

lib/providers 폴더 안에 있는 녀석들이 서로 어떻게 연결되어 있는지 보여줍니다.

neurology
Main (App)
MultiProvider
AuthProvider
로그인 여부, 내 정보(ID, 이름) 관리. 앱의 '문지기' 역할.
TeamProvider
현재 선택된 팀, 다크모드 설정, Wi-Fi 설정 관리.
TaskProvider
업무 목록, 필터링 로직. (TeamProvider의 TeamID를 참조함)
Journal/Chat
일지 및 메신저 데이터. (주기적으로 Polling하여 동기화)

04. 파일 구조도 (Project Map)

프로젝트의 각 폴더가 어떤 역할을 하는지 정리한 지도입니다.

📂 lib/ (핵심 코드)
  • description main.dart - 앱의 시작점. Provider 등록.
  • description models.dart - 데이터 그릇 (Task, User 등 정의)
📂 lib/providers/ (상태 관리)
  • description auth_provider.dart - 로그인/회원가입 로직
  • description team_provider.dart - 설정 & 팀 관리
  • description task_provider.dart - 업무 데이터 관리
📂 lib/tabs/ (화면 UI)
  • description home_tab.dart - 홈 화면 (차트)
  • description task_tab.dart - 업무 목록 화면
  • description messenger_tab.dart - 채팅 화면
📂 lib/services/ (백엔드 통신)
  • description drive_service.dart - 구글 드라이브 API 연결 담당

05. 2중 로그인 원리 (Security)

왜 로그인을 두 번 해야 하는지, 각 로그인의 역할이 무엇인지 설명합니다.

1

Google 로그인 (Door Key)

"이 구글 드라이브(창고)를 쓸 권한이 있는가?"를 확인합니다.

목적: API Access Token 획득
공유: 팀원 모두가 같은 계정을 사용해야 같은 데이터를 봅니다.
2

App 로그인 (ID Card)

"이 창고 안에서 너는 누구인가?"를 식별합니다. (글쓴이 기록용)

목적: 작성자 구분 (김반장 vs 이대리)
데이터: worknote_users.json 파일에 ID/PW가 저장됩니다.
